# Halium kernel from the LineageOS 20 tree (Phase 3 of the LineageOS 20 roadmap)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `./droidian/build-kernel.sh` builds a Halium-capable 4.9.337 kernel
from the exact LineageOS tree Phase 2 shipped, packaged as the same
`linux-image-*` / `linux-bootimage-*` .debs as today, and when flashed to
slot b over LineageOS 20's `vendor` and `dtbo` the phone reaches the Halium
initramfs and answers SSH over USB.

**Architecture:** `build-kernel.sh` keeps its shape (clone a pinned tree,
overlay `droidian/packaging/`, apply patches, build in the Droidian
container, extract images). Only the pin, the toolchain, the defconfig and
the patch set change. Every out-of-tree edit is a committed patch or a
defconfig line; the tree itself is never hand-modified. The LineageOS
`.config` and `dmesg` captured in Phase 2 are the reference every
divergence is measured against.

**Tech Stack:** `releng-build-package` in `quay.io/droidian/build-essential:current-amd64`,
`clang-android-14.0-r450784d`, `linux-initramfs-halium-generic`, podman.

## Global Constraints

- Source pin: `LineageOS/android_kernel_oneplus_sdm845` @
  `7fbf93e229443b8366c18eaa0ea70dd499749e37` (tip of `lineage-20`,
  4.9.337, `techpack/audio` in-tree). Same commit `lineage/local_manifest.xml`
  pins; the kernel Phase 2 booted reports `4.9.337-g7fbf93e22944`.
- Compiler: `clang-android-14.0-r450784d`. LineageOS's running kernel
  reports `clang version 14.0.6 ... r450784d` (`logs/lineage20/kernel-version.txt`).
  Match it; a different clang is a variable we do not need.
- Zero out-of-tree edits: `build-kernel.sh` must produce the images from
  the pinned commit plus `droidian/packaging/` alone.
- Slot discipline: everything flashes to slot **b**, over LineageOS's
  `vendor_b` and `dtbo_b`. Slot a is not touched by this phase.
- Never `fastboot -w`. Never erase `dtbo`.
- Long runs launch as `setsid nohup ... > log 2>&1 < /dev/null &`; poll
  the log in separate commands. Never edit a running script.
- No AI attribution in commits. Conventional commits.

**The toolchain.** `quay.io/droidian/build-essential:current-amd64` has
`clang-android-14.0-r450784d` (candidate `13.0.0+r2+z1+git20250320...`)
and `linux-initramfs-halium-generic` (`2025.04.11.0`). Both resolved by
`apt-cache policy` inside the image, not assumed.

**The reference kernel.** LineageOS 20's kernel is monolithic: `lsmod` is
empty and `/vendor/lib/modules` holds 12 unused files. Its `dmesg`
(`logs/lineage20/dmesg.txt`, 5885 lines) shows every PIL subsystem
loading: `ipa_fws` 6.7 s, `adsp` 9.5 s, `cdsp` 9.6 s, `slpi` 9.9 s,
`modem` 12.0 s (`Power/Clock ready` 14.4 s), `venus` lazily at 56 s. Each
is preceded by `error -13` lines from the first (userspace helper) load
path; that pattern is healthy. `-13` **without** the following
`loading from 0x...` line is a regression.

**The current packaging.** `droidian/packaging/debian/kernel-info.mk` today:
`KERNEL_BASE_VERSION = 4.9-113`, `BUILD_CC = aarch64-linux-android-gcc-4.9`,
`BUILD_PATH = /usr/lib/llvm-android-6.0-4691093`, `DEB_TOOLCHAIN` names
`clang-android-6.0-4691093` and the gcc-4.9 cross packages,
`KERNEL_BOOTIMAGE_PATCH_LEVEL = 2018-12`, `KERNEL_BOOTIMAGE_VERSION = 0`,
`KERNEL_BUILD_TARGET = Image.gz-dtb`, `KERNEL_IMAGE_WITH_DTB_OVERLAY = 0`.
Four patches in `droidian/packaging/patches/`:
`0001-u_ether` (NCM null skb), `0002-loop` (discard vs punch_hole),
`0003-msm-poweroff` (ramoops knobs), `0004-adsprpc` (bounded invoke).

**What Phase 2 flashed to slot b** (`lineage/out/`, SHA256SUMS verified):
`boot.img` 64 MiB, `dtbo.img` 8 MiB, `vbmeta.img` 8 KiB, `vendor.img`
607 MiB sparse, `system.img`. This phase replaces `boot_b` and `vbmeta_b`
only.

**LineageOS's boot.img header, read from the image** (python `struct` on
the 1648-byte header, not from documentation):

| Field | LineageOS 20 | Our `kernel-info.mk` today | Change |
|---|---|---|---|
| `header_version` | **1** | `KERNEL_BOOTIMAGE_VERSION = 0` | -> 1 |
| `os_version` / patch level | 13.0.0 / **2026-02** | `KERNEL_BOOTIMAGE_PATCH_LEVEL = 2018-12` | -> 2026-02 |
| `page_size` | 4096 | 4096 | none |
| `kernel_addr` | `0x00008000` | `0x00008000` | none |
| `ramdisk_addr` | `0x01000000` | `0x01000000` | none |
| `tags_addr` | `0x00000100` | `0x00000100` | none |
| `second_size` | 0 | `SECONDIMAGE_OFFSET` set but unused | none |
| `recovery_dtbo_size` | 0 | n/a | none |
| kernel / ramdisk | 14.95 MB / 13.41 MB | | reference sizes |

Header v1 matters: the bootloader that booted LineageOS expects v1 and our
current kernel package emits v0. The patch level matters less for boot but
a lower one than what is on the slot can trip the bootloader's anti-rollback
on some devices; matching LineageOS's is free.

- [ ] **Step 2: Write `halium.delta` by reviewing `/tmp/only-ours.txt` line by line**

The file is the list of options to apply ON TOP of LineageOS's
`enchilada_defconfig`. Format: `CONFIG_X=y   # why`, or
`# CONFIG_X is not set   # why`. Start from Halium's documented
requirements (`halium/halium-boot` `kernel-config-checker` expectations)
and keep only what is in `/tmp/only-ours.txt` for a reason you can name:

```
# --- containers (lxc runs the Android vendor) ---
CONFIG_PID_NS=y                 # lxc
CONFIG_UTS_NS=y                 # lxc
CONFIG_IPC_NS=y                 # lxc
CONFIG_USER_NS=y                # lxc, unprivileged mounts
CONFIG_CGROUP_DEVICE=y          # lxc device cgroup
CONFIG_CGROUP_FREEZER=y         # lxc freeze on suspend
CONFIG_CHECKPOINT_RESTORE=y     # lxc
# --- systemd / udev ---
CONFIG_FHANDLE=y                # systemd, name_to_handle_at
CONFIG_DEVTMPFS=y               # udev
CONFIG_DEVTMPFS_MOUNT=y         # udev
CONFIG_SYSVIPC=y                # systemd, pulseaudio
CONFIG_AUTOFS4_FS=y             # systemd automount
CONFIG_CGROUPS=y                # already in LineageOS, listed for the checker
# --- security: Droidian boots security=apparmor apparmor=1 ---
CONFIG_SECURITY_APPARMOR=y      # Droidian cmdline
CONFIG_DEFAULT_SECURITY_APPARMOR=y
# CONFIG_DEFAULT_SECURITY_SELINUX is not set   # one default LSM
# --- modules: halium ships unsigned modules ---
# CONFIG_MODULE_SIG is not set
# CONFIG_MODULE_SIG_FORCE is not set
# --- console / display ---
CONFIG_VT=y                     # virtual terminal, phosh recovery
CONFIG_VT_CONSOLE=y
CONFIG_FB=y
CONFIG_FB_VIRTUAL=y             # cmdline video=vfb:...
# --- halium initramfs ---
CONFIG_USB_CONFIGFS_NCM=y       # already LineageOS, SSH over USB
CONFIG_USB_CONFIGFS_RNDIS=y     # windows hosts
CONFIG_EXT4_FS=y                # already
CONFIG_SQUASHFS=y               # rootfs.img is squashfs in some builds
```

The list above is a STARTING POINT to be checked against
`/tmp/only-ours.txt`, not the answer: an option is only added to
`halium.delta` if it (a) appears in `/tmp/only-ours.txt` and (b) has a
reason. Options in `/tmp/only-ours.txt` with no reason are the ones being
deliberately dropped; list them in the commit message under "dropped".

- [ ] **Step 3: Write `droidian/kernel-config-check.sh`**

Halium's checker is a script in `halium/halium-boot`; rather than vendor
it, encode the same idea in 30 lines: every `=y` line in `halium.delta`
must appear in the final `.config`, every `is not set` must not be `=y`.
Run it against the `.config` the build produces (`build-kernel.sh` leaves
it at `$KERNEL_DIR/.config`; copy it to `droidian/out/config-4.9-337`).

```bash
#!/usr/bin/env bash
# kernel-config-check — every line in halium.delta must hold in a .config.
set -euo pipefail
delta="${1:?halium.delta}"; cfg="${2:?.config}"; rc=0
while IFS= read -r line; do
    line="${line%%#*}"; line="${line%"${line##*[![:space:]]}"}"
    [ -n "$line" ] || continue
    case "$line" in
        *"is not set")
            k="${line#\# }"; k="${k% is not set}"
            grep -qE "^$k=y" "$cfg" && { echo "FAIL $k is set, delta wants it off"; rc=1; } ;;
        *=*)
            grep -qxF "$line" "$cfg" || { echo "FAIL $line"; rc=1; } ;;
    esac
done < "$delta"
[ $rc -eq 0 ] && echo "ALL $(grep -cvE '^\s*(#[^C]|$)' "$delta") delta lines hold"
exit $rc
```
